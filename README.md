# Установка и запуск

## Что нужно установить

1. **Python 3.10+**
   В коде используется современный синтаксис типов (`dict[str, tuple[...]]`,
   `str | None`) — на более старой версии будет `SyntaxError`.

2. **Ollama** (https://ollama.com) — LLM работает локально, без внешних
   API-ключей и облачных сервисов. После установки сервис должен слушать
   `http://localhost:11434`.

3. **Модель в Ollama** — та же, на которой тестировался проект:
   ```
   ollama pull llama3.2
   ```
   Если запускаете с другой моделью (`python demo.py --model qwen2.5:7b`),
   ответы LLM могут отличаться от того, что видели при разработке — это
   нормально, но стоит иметь в виду при демонстрации.

## Настройка окружения

```bash
python3 -m venv venv
# Windows (PowerShell):
venv\Scripts\Activate.ps1
# Linux/macOS:
source venv/bin/activate

pip install -r requirements.txt
```

## Проверка перед демонстрацией

Сначала — без Ollama, чтобы убедиться, что сам проект и все импорты рабочие:
```bash
python demo.py --fake
```

Если это отработало без ошибок, переходите к реальному запуску:
```bash
python demo.py
```

Если `python demo.py --fake` работает, а обычный `python demo.py` — нет,
проблема в Ollama (не запущен сервис / не загружена модель), а не в коде.
Проверить Ollama отдельно от проекта:
```bash
ollama run llama3.2
```
Если модель отвечает здесь, но зависает через скрипт — скорее всего,
дело в том, что первый запрос после старта модели небольшой запас времени
занимает загрузка весов в память; таймаут в `orchestrator/llm_client.py`
сейчас стоит 5 минут (`timeout=300.0`) с запасом на это.

## Для агентов качества / надёжности / оптимизации

Оркестратор ничего не знает о том, как вы получили свои цифры (какая
модель, какие признаки) — ему нужен только **результат в согласованном
формате**. Он принимает JSON и парсит его в `orchestrator/json_io.py`
(функция `parse_agent_inputs`).

**Где смотреть, что именно нужно вернуть:**

- `orchestrator/contracts.py` — точный список полей и их смысл для каждого
  агента (`QualityAssessment`, `ReliabilityAssessment`,
  `OptimizationScenario`/`OptimizationOutput`). Комментарии там объясняют,
  что означает каждое поле.
- `sample_data/*.json` — готовые примеры JSON, по одному на сценарий,
  можно смотреть просто как образец структуры (значения там придуманы,
  не из реальных данных).
- `orchestrator/hard_constraints.py` — что именно из ваших полей реально
  используется в проверках. Это самое важное: если поле не участвует
  в проверках, его формат менее критичен; если участвует — совпадение
  формата обязательно.

**Почему именно такой набор полей** — он выведен не произвольно, а из
того, что оркестратору реально нужно посчитать жёсткие ограничения
(ТЗ, раздел 4) и собрать объяснение для оператора (ТЗ, раздел 5):

| Поле | Зачем оркестратору |
|---|---|
| `quality.predicted_quality["sulfur_mg_kg"]` | сравнение с пределом по сере — жёсткая проверка |
| `reliability.regime_allowed` | если `false` — оркестратор сразу отказывает, без сценариев |
| `reliability.optimization_constraints` | границы параметров, чтобы проверить, не вышел ли сценарий за допустимый диапазон |
| `optimization.scenarios[].parameter_changes` | что именно меняется — сверяется с диапазонами выше |
| `optimization.scenarios[].expected_quality` | прогноз качества конкретного сценария — тоже проверяется на предел |
| `optimization.scenarios[].within_hard_limits` | собственная оценка агента оптимизации (учитывается, но не заменяет перепроверку) |
| `state.lims_age_minutes` | проверка на устаревшие данные — если превышен порог, рекомендация не выдаётся |

Остальные поля (`confidence`, `risk_index`, `risk_class`, `assumptions` и
т.п.) не участвуют в жёстких проверках напрямую, но передаются в LLM и
влияют на текст объяснения оператору — их можно заполнять как есть,
формат не настолько критичен.

**Если ваши модели будут выдавать другие имена полей** — не страшно,
менять нужно будет только `parse_agent_inputs` в `json_io.py`, остальной
оркестратор трогать не придётся (см. докстринг в начале этого файла).
Пришлите один реальный пример вашего JSON — нужно будет парсить под него.
