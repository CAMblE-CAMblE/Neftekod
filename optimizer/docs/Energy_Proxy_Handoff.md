# Energy Proxy - Handoff

## Назначение

`energy_proxy.py` оценивает условное энергопотребление каждого сценария.

Это **не физический расчет реального расхода энергии** и не кВт·ч. Используется относительный показатель:

**EU/h — условные энергетические единицы в час.**

Базовый текущий режим принимается за:

```text
100 EU/h
```

Цель — получить численно сравнимую стоимость разных технологических режимов для последующего Pareto-анализа.

---

## Входные данные

Используются:

```text
optimizer/examples/base_state.csv
optimizer/logs/scenarios.csv
optimizer/examples/controllable_bounds.csv
```

### `base_state.csv`

Текущее состояние установки.

Для каждого управляемого параметра определяется его текущее значение.

### `scenarios.csv`

Набор сценариев от `scenario_generator.py`.

Обязательно содержит:

```text
candidate_id
```

и значения управляемых параметров.

### `controllable_bounds.csv`

Определяет актуальный список управляемых параметров:

```text
parameter,lower_bound,upper_bound
```

Energy Proxy использует только колонку `parameter`.

---

## Определение типа параметра

Тип параметра определяется по имени тега.

Предусмотрены категории:

```text
temperature
pressure
flow
unknown
```

Примеры:

```text
hdt_T6  → temperature
hdt_P13 → pressure
hdt_F9  → flow
```

Неизвестные параметры пока не участвуют в расчете энергетического proxy.

---

## Энергетическая модель

### Температура

Рост температуры считается дополнительным энергозатратным режимом.

Используется относительное изменение:

```text
ΔT = (T - T_base) / |T_base|
```

При `ΔT > 0` добавляется энергетический расход:

```text
E_T =
    temperature_coefficient
    × ΔT
    × BASE_ENERGY
```

Снижение температуры не создает отрицательного расхода.

---

### Давление

Повышение давления также увеличивает proxy:

```text
ΔP = (P - P_base) / |P_base|

E_P =
    pressure_coefficient
    × ΔP
    × BASE_ENERGY
```

Снижение давления не создает отрицательного расхода.

---

### Расход

Для расхода используется нелинейная зависимость:

```text
flow_ratio = F / F_base

E_F =
    flow_coefficient
    × (flow_ratio ^ exponent - 1)
    × BASE_ENERGY
```

Текущие параметры MVP:

```text
BASE_ENERGY = 100 EU/h

temperature_coefficient = 0.03
pressure_coefficient = 0.02

flow_coefficient = 0.50
flow_exponent = 2.0
```

Эти коэффициенты являются **явными допущениями MVP**, а не подтвержденными паспортными характеристиками оборудования.

## Результат

Создается:

```text
optimizer/logs/energy_results.csv
```

Основные поля:

```text
candidate_id
energy_proxy_eu_h
```

Дополнительно сохраняется вклад каждого параметра:

```text
energy_hdt_T6
energy_hdt_P13
energy_hdt_F9
...
```

Это позволяет объяснить, почему энергетический proxy изменился.

---

## Интерпретация

Например:

```text
candidate_id = 0
energy_proxy_eu_h = 100.0
```

означает текущий базовый режим.

Если:

```text
candidate_id = 7
energy_proxy_eu_h = 106.8
```

то сценарий считается условно на **6.8% более энергозатратным относительно базового режима**.

Не следует интерпретировать `106.8 EU/h` как реальные 106.8 кВт·ч.

---

## Ограничения

`energy_proxy.py`:

* не проверяет качество;
* не проверяет технологические ограничения;
* не выбирает лучший сценарий;
* не строит Pareto front;
* не использует реальные энергометрические данные;
* не заменяет технологическую модель оборудования.

Его единственная задача — дать сопоставимый энергетический показатель для сценариев.

```text
quality_results.csv
        +
energy_results.csv
        ↓
candidate_id
        ↓
отбросить quality_feasible = False
        ↓
Pareto front
        ↓
выбор финального сценария
```

На следующем этапе энергетический proxy должен использоваться как **один из критериев оптимизации**, а ограничение качества по сере остается жестким.
